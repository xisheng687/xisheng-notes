重度使用了几天的 claude opus 5.5，我已经不想使用 ChatGPT了。

先看下老外是咋说的。

![](https://xisheng687.github.io/xisheng-notes/assets/posts/2026-09-28-use-claude-opus-5-5/body-01.png)

Danny Postma 说，Opus 5.5 最让他惊喜的是速度：等待时间几乎为零，使用时更像自己在连续完成工作，而不是等一位同事回复。这个评价对应我前面提到的“速度更快”。

也有的说，Opus 5.5 最适合编程；他和团队在真实生产系统中用它处理复杂工程任务，结果令他满意。

我个人感觉，对比 gpt，claude opus 5.5 的优势如下：

1.更耐用，额度消耗比 gpt6 sol 更低。

2.审美比 gpt 好多了，用来做前端更轻松。

3.速度更快。

4.同一个项目下面，即使你不开分支，不同的窗口在改动的时候如果出现了冲突，内部也会互相提醒，真是编程小白的救星。

5.写作能力回来了，比 gpt 好十条街了。

6.很聪明，基本知道你要什么，只要你啰嗦一点，他就能心领神会，吭哧吭哧干活。

这里吐槽一下 gpt，经常会说：我会持续监督，2 个小时之后汇报情况。

然后什么都没有，任务就停止了。但是 claude 真的会持续监督并自己优化自己测试然后继续自己监督！

所以一些流量大的网站，我会直接让 claude 优化之后，直接部署测试，他会持续检测这个优化或者改动之后，用户的数据到底是更好了还是更差了，比如跳出率，停留时间，包括其他更详细的数据——最好提前把谷歌分析，谷歌 gsc 包括微软clarity的数据给他，可以分析得更加全面。

所以你会发现，你现在可以直接用 claude 做数据搜集，同行调研，博客文章写作，前端页面设计，后端开发，用户数据分析，搞定做网站的一条龙服务。

好像没有用其他模型的理由了……唯一美中不足的是，没办法作图。

所以我现在的用法一般是：

1.让 claude 做总调度，需要作图，就让 claude 自己调用 codex 去作图，当然，用 grok 也可以。

2.如果比较难的事情，就让 claude 先和 codex 一起探讨，一直探讨到没有意见之后再开始执行。必要的时候可以拉上 grok。因为 codex 有插件，grok 有 cli，claude 都可以很方便地调用。

3.如果想进一步节省 token，可以让 claude 做计划，codex 做苦力活负责代码和初审，然后 claude 最后再审查一下就可以了。

我知道很多人可能会吐槽，可是我的账号被封了啊。

说一下我的做法。

我也被封过一个，目前我的做法如下，还稳定活着。

1.用静态住宅 ip，不要乱七八糟的机场路线。

2.我第一个claude 账号被封之后，我没有换 ip，还是同一个 ip 注册的新号。

3.我把新的 claude 放在了一台新的 mac mini 上面，mac mini 上面的时区设置是台北，语言是英文，然后关闭定位。

4.可以让 codex 开发一个小插件，一旦你的海外 ip 断了，立刻切断 claude。

最后，一个省钱小技巧和建议。

Mac mini 本来是性价比之王（我买了两台了已经），但是最近半年涨价太离谱了，所以可以去购买【无头骑士】当做 mac mini 平替——也就是少了一个屏幕的 MacBook 笔记本——性价比很高。

![](https://xisheng687.github.io/xisheng-notes/assets/posts/2026-09-28-use-claude-opus-5-5/body-03.png)

因为 claude 太强大了，我可以同时做四五个项目，开十几个任务一起跑……唯一限制住我的，就是mac 老是因为内存不够而卡死。。
